## 安逸的漂移威胁：逐渐不理解自己在做什么

The threat is comfortable drift toward not understanding what you're doing

**发布时间**: 2026-04-05 09:57

**链接**: [https://ergosphere.blog/posts/the-machines-are-fine/](https://ergosphere.blog/posts/the-machines-are-fine/)

**描述**:

文章通过对比两位天体物理学博士生（爱丽丝与鲍勃）的研究经历，探讨了AI工具对学术训练的根本性冲击。爱丽丝通过传统方式亲历阅读、编程、纠错等过程，获得了扎实的科研能力与直觉；而鲍勃依赖AI代理完成从读文献到写论文的大部分工作，虽然产出了相似的论文，却未能在过程中构建起个人的深层理解。文章指出，当前学术评价体系只重可量化的产出（如论文数量），却忽视了科研人才培养中无法量化的核心——即通过亲身实践、试错与思考所获得的独立研究能力与判断力。若学者为追求效率而将核心思考外包给AI，虽能短期加速产出，却可能丧失科学探索中最不可替代的部分：人的成长与真正理解。问题的关键不在于是否使用AI，而在于如何将其用作辅助思考的工具，而非替代思考本身。

**评论要点**:

评论讨论了使用AI模型处理开放式任务的方法，强调通过观察模型输出是否变得模糊或矛盾来暂停，并借助外部知识或定量评估来校准模型，从而继续推进。尽管此方法比专家直接操作更慢且易错，但远优于无AI辅助。针对模型改进的常见反驳，有观点认为单纯扩大模型规模并非可持续方案，因为复杂问题需要更长的训练时间、更多计算资源且难以验证，RLVR也存在类似挑战。部分评论者指出，质疑者可能未仔细阅读原评论，因为其问题已在原文明确回答，并建议更真诚地参与讨论。

**链接**: [https://github.com/JuliusBrussee/caveman](https://github.com/JuliusBrussee/caveman)

**描述**:

这是一个名为“caveman”的Claude Code技能/插件项目，其核心是让AI助手（如Claude）以类似“穴居人”的极简风格进行对话。这种方法能大幅减少AI回复的令牌使用量，平均可节省约75%的输出令牌，同时保持技术内容的完整性和准确性。项目提供了安装方法和使用指令，并通过基准测试展示了其在多种编程任务中的显著效果。其原理是去除冗余的礼貌用语、填充词和修饰语，只保留核心信息，从而提升响应速度、降低使用成本，并让回复更易于阅读。

**评论要点**:

评论讨论了代码压缩风格（如"穴居人式"缩写）与详细表达的可读性对比。一方认为缩写（如"caveman speak"）因缺乏惯例而难以快速理解，降低了阅读速度；另一方则提及Meta内部实际推行此类实践。关键争议在于简洁性与可读性之间的权衡：详细代码便于"自动模式"速读，而过度压缩虽减少字符但增加认知负担。讨论未涉及具体技术工具，但突出了编码风格对开发效率的影响。

## AWS工程师报告Linux 7.0导致PostgreSQL性能减半，修复可能不易

AWS engineer reports PostgreSQL perf halved by Linux 7.0, fix may not be easy

**发布时间**: 2026-04-05 00:13

**链接**: [https://www.phoronix.com/news/Linux-7.0-AWS-PostgreSQL-Drop](https://www.phoronix.com/news/Linux-7.0-AWS-PostgreSQL-Drop)

**描述**:

亚马逊工程师报告称，即将发布的Linux 7.0内核导致PostgreSQL数据库性能下降约一半。问题根源在于新内核限制了可用的内核抢占模式，移除了默认的PREEMPT_NONE选项，导致用户空间自旋锁耗时大幅增加。尽管已提交恢复该选项的补丁，但核心开发者认为正确的解决方案是让PostgreSQL适配Linux 7.0新引入的“可重启序列时间片扩展”功能，而非回退内核更改。这意味着，除非PostgreSQL进行相应更新，否则在其适配前，用户在某些场景下可能面临显著的性能下降。Linux 7.0稳定版预计约两周后发布，并将成为Ubuntu 26.04 LTS的默认内核。

**评论要点**:

评论主要讨论了自旋锁（spin-wait）在实现中的问题，包括在临界区仍可能因中断或他人争用锁而性能不佳，以及指数退避策略容易因内核调度器的微小随机行为差异导致显著性能衰退（“过拟合”）。其次，针对Splunk软件，指出其因捆绑PostgreSQL、Python、MongoDB等组件（而非依赖检查）带来了安全更新难题，并建议禁用透明大页（THP）以适应其小规模读写特性。此外，有观点提出可通过将线程固定到特定核心并移出其他线程来手动调度，理想情况下动态调度器应自动实现此优化。

Lisette a little language inspired by Rust that compiles to Go

**描述**:

Lisette 是一门受 Rust 启发、语法类似 Rust 的新编程语言，其独特之处在于它编译为 Go 代码并运行在 Go 运行时上。它融合了 Rust 的诸多现代特性，如代数数据类型、模式匹配、默认不可变、Hindley-Milner 类型系统，并彻底摒弃了 nil。同时，它保持了与 Go 生态系统的无缝互操作性。该语言旨在提供更强的安全性，在编译时捕获许多常见的 Go 运行时错误，并提供管道操作符、try 块、序列化属性等符合人体工程学的语法。最终，Lisette 代码会透明地编译成可读性强的 Go 代码。

**评论要点**:

Rust的学习曲线更陡峭，熟悉TypeScript的开发者能在一周内上手C#并产出。C#的Web技术栈被认为更成熟、更易用。Go的异步模型通过在每次函数调用前插入检查协程切换的代码来实现，这带来了性能开销，但该机制也用于GC检查和栈保护。追求零成本抽象的语言无法采用这种设计，因此出现了函数着色问题。评论者认为Rust和C#适用于不同场景，Go的异步实现方式与零成本抽象语言存在根本差异。
