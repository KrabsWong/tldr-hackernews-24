## Zed编辑器将图形库从blade切换至wgpu

Zed editor switching graphics lib from blade to wgpu

**发布时间**: 2026-02-13 14:03

**链接**: [https://github.com/zed-industries/zed/pull/46758](https://github.com/zed-industries/zed/pull/46758)

**描述**:

该文章主要讨论了Zed编辑器的一个拉取请求，旨在移除原有的Blade图形库，并在Linux平台上改用WGPU（WebGPU）作为渲染后端。核心原因是Blade库存在诸多问题，而WGPU作为Rust生态中图形处理的事实标准，能解决现有问题、提升兼容性，并受益于其活跃的社区发展。维护者对此表示兴趣并进行了代码审查。讨论还涉及WGPU在内存占用、跨平台潜力（如macOS/Windows）以及与原生渲染器性能对比等方面的权衡。最终，该更改被合并，并带来了内存使用优化和一定的CPU性能提升。

**评论要点**:

评论主要讨论了三个独立的技术问题。首先，明确 wgpu 是专注于 GPU 渲染的底层 API，本身不处理字体堆栈或文本渲染等高级功能。其次，用户报告了 Zed 编辑器在长对话时代理面板崩溃、终端中 Claude 代码渲染异常，以及 ESLint 对 TypeScript 的错误检查不稳定等问题，并将其与 VS Code 和 iTerm 的稳定性进行了对比。最后，针对如何在 Rust 中使用 Vulkan 1.4，评论提出了两种技术路径的争议：一是使用 bindgen 处理 C 头文件，二是自行编写 vk.xml 生成器，这反映了在集成底层图形 API时对工具链选择的不同考量。

## 开源不是为了你（2018）

Open source is not about you (2018)

**发布时间**: 2026-02-13 14:36

**链接**: [https://gist.github.com/richhickey/1563cddea1002958f96e7ba9519972d9](https://gist.github.com/richhickey/1563cddea1002958f96e7ba9519972d9)

**描述**:

文章核心观点是：开源软件的本质是提供源代码和使用许可，而非对用户承担无限责任。项目维护者没有义务因开源而转变为社区经理或满足用户的所有需求。用户无权要求特定功能、贡献被接纳或获得维护者的关注。开源并非“社区驱动开发”的神话，维护者有权自主决定项目方向。文章以Clojure为例，说明核心团队投入个人资源进行开发，但拒绝接受外界对开发流程的指责。作者强调，如果用户对项目不满，应自行创建分支或启动新项目，而非指责原创者。开源应被视为一种无附加条件的馈赠，而非满足集体权利的工具。

**评论要点**:

评论主要围绕开源软件维护者的责任展开。核心观点认为，公开发布软件意味着承担一定责任，不能仅凭免责声明就免除道德和伦理义务。作者以glibc和OpenSSL为例，强调若维护者蓄意破坏或随意更改关键功能，将导致混乱，而“概不负责”的态度不可接受。争议点在于：部分开发者认为用户无权要求支持或合并PR，而作者指责这种敌对态度损害开源生态，甚至接近发布有害软件。建议对广泛使用的软件设立支持门槛，否则应闭源。同时批评了只为博取声望而开源、却拒绝贡献的行为。另一则简短评论提及“礼物经济”概念的不同理解，但未深入。总体共识是开源维护者需平衡自由与责任，过度防御性态度不利于社区发展。
