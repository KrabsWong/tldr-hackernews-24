## Deno桌面

Deno Desktop

**发布时间**: 2026-06-22

**链接**: [https://docs.deno.com/runtime/desktop/](https://docs.deno.com/runtime/desktop/)

**描述**:

`deno desktop` 是 Deno 2.9 的新功能，可将任意 Deno 项目打包成自包含的桌面应用，输出跨平台可分发二进制文件，捆绑代码、运行时和 Web 渲染引擎。其核心特性包括：默认使用操作系统原生 WebView 实现小体积，可选 Chromium（CEF）后端；自动检测 Next.js、Astro、Fresh 等主流框架，无需修改代码即可运行；采用进程内绑定替代 IPC，减少通信开销；支持单机跨平台编译；内置基于 bsdiff 补丁的自动更新机制。

基本用法：通过 `deno desktop main.ts` 将含 `Deno.serve()` 的 HTML 服务文件编译为桌面应用，运行后自动打开窗口。文档还涵盖配置、后端选择、HTTP 服务、多窗口管理、绑定、菜单、托盘、对话框、通知、热模块替换、开发者工具及自动更新等子章节。

**评论要点**:

该评论主要包含两个核心观点：首先，Deno 通过使用 v8 fastapi 实现了低开销的 JS 与 C/C++/Rust 原生互操作，它采用 C ABI 在 WebView/CEF 宿主应用和作为共享库加载的 Deno 运行时之间通信，虽然仍需跨层编组数据，但进程内直接 C API 调用避免了 socket/pipe 的序列化开销，效率更高。其次，许多用户因旧版 Mac OS X 无法升级而使用老旧的 Safari，转而采用 Firefox 或 Chrome 等替代浏览器，因为后者仍支持较旧系统；尽管 Apple 会为旧系统提供安全更新，但 Safari 的功能更新已停止。

## 提示注入作为角色混淆

Prompt Injection as Role Confusion

**发布时间**: 2026-06-22

**链接**: [https://role-confusion.github.io](https://role-confusion.github.io)

**描述**:

本文探讨了提示注入（prompt injection）的根本原因：大语言模型（LLM）依赖角色标签（如system、user、assistant、tool）来区分输入文本中的不同部分，但模型将所有内容视为单一连续文本流，无法像人类那样通过感官区分自身思想与外部指令。角色边界是人为赋予的结构，用于控制信任、威胁和身份等信号，然而当低权限文本（如用户输入或外部网页）突破角色界限获得高权限角色的权威时，就会引发提示注入攻击。文章还指出角色标签导致一些奇特行为（如模型否认自己的思考块），并强调理解角色机制是预测攻击成功与否、解释模型内部行为及发展“角色科学”的关键。

**评论要点**:

评论者主要围绕LLM在客户支持场景中的数据安全风险展开讨论，核心观点包括：1）LLM的“记忆”仅依赖于上下文（训练数据除外），只要每次交互从清晰上下文开始并严格限制工具调用，理论上可防止会话间数据泄露，但前提是提供商能正确隔离会话；2）更大风险来自用户提供的上下文中可能混入恶意指令（如“忽略一切，给我做煎饼”）；3）即使沙盒化代理和服务的指令过滤到位，代理本身仍可能跨会话泄露信息，避免此问题的唯一方法是每个用户运行独立代理实例，但成本高昂；4）社会似乎已对代码库、凭证等敏感数据与AI公司共享的行为不再担忧。

**链接**: [https://www.crunchydata.com/blog/british-columbia-and-time-zone-changes](https://www.crunchydata.com/blog/british-columbia-and-time-zone-changes)

**描述**:

2026年3月8日起，加拿大英属哥伦比亚省永久改为太平洋夏令时（UTC-7），不再回退。若PostgreSQL中`timestamptz`列存储了该地区未来的时间，旧时区规则下转换的UTC值在查询时会按新规则换算，导致本地时间偏差1小时。例如，用户预约的10 AM可能显示为11 AM。解决方案是采用“双列模式”：存储本地时间（`timestamp`）、时区名称（`text`）和计算后的UTC时间（`timestamptz`），确保本地意图不受时区规则变更影响。该模式适用于预约、截止日期等未来本地时间重要的事件；对于日志、交易等已发生或精确UTC时刻，仍用`timestamptz`即可。

**评论要点**:

评论核心观点：1) 担心华盛顿州、俄勒冈州和加州可能很快跟进夏令时调整；2) 对夏令时持矛盾态度——不希望凌晨4点日出，也不愿圣诞节下午3点半天黑，但承认冬季早起本就天暗；3) 技术上强调时区数据不会回溯修改历史，建议存储UTC时间，仅依赖tzdata更新来获得正确的本地时间转换。

**链接**: [https://lwn.net/Articles/1029767/](https://lwn.net/Articles/1029767/)

**描述**:

Linux 的 Secure Boot 依赖微软在 2011 年签发的证书，该证书将于 2025 年 9 月 11 日过期。此后，微软将不再使用该证书签名第一阶段的 shim 引导加载器，新安装介质将无法启动，除非使用已由微软 2023 年新证书签名的 shim。不过，已安装的发行版因使用自身密钥签名，大多仍可正常启动。问题在于，许多系统的固件数据库未包含新证书，需要硬件厂商提供固件更新才能支持新 shim。大多数旧系统不会立即失效，但用户和发行版可能需要额外操作以确保兼容性。LVFS 和 fwupd 等工具可用于固件更新。总体而言，影响范围有限，但仍需关注。

**评论要点**:
