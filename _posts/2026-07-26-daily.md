## 干掉Cookie横幅

Kill The Cookie Banner

**发布时间**: 2026-07-26

**链接**: [https://killthecookiebanner.eu/](https://killthecookiebanner.eu/)

**描述**:

该网站是欧洲公民社会组织发起的“Kill the Cookie Banner”倡议，旨在推动欧盟废除误导性的Cookie横幅。文章指出，欧盟隐私法默认禁止在线追踪，Cookie横幅实为追踪行业为诱导用户放弃权利而设计的工具，导致高达90%的人点击“同意”，而真正愿意被追踪的仅约3%。2025年秋，欧盟委员会在“Digital Omnibus”改革中提出用浏览器自动信号替代Cookie横幅，让用户一次性设定隐私偏好，但谷歌及追踪行业游说多个成员国和欧洲议会阻挠该提案。网站呼吁公众联系欧洲议会议员和本国代表，施压推动废除Cookie横幅。

**评论要点**:

有评论认为GDPR合规要求本质上形同虚设，将网站收集用户数据比作“卖淫”，暗示其具有剥削性。另一观点则强调合规并非强制，个人网站或应用完全可以不设Cookie横幅，只要不存储个人身份信息即可，技术选择是自由的。

分歧集中在“合法利益”条款的滥用上：一方担忧新插件会助长网站利用该漏洞，默认配置数百个“合法利益”合作伙伴，远超必要范围；另一方则坚持合规工具本身是中性的，关键在于网站是否诚实执行规则。整体上，讨论围绕数据收集的伦理边界与监管执行的有效性展开，但未形成统一结论。

## GrapheneOS针对锁定设备数据提取的防护措施

GrapheneOS protections against data extraction from locked devices

**发布时间**: 2026-07-26

**链接**: [https://discuss.grapheneos.org/d/40700-grapheneos-protections-against-data-extraction-from-locked-devices](https://discuss.grapheneos.org/d/40700-grapheneos-protections-against-data-extraction-from-locked-devices)

**描述**:

这篇文章介绍GrapheneOS针对锁定设备数据提取的防护机制。文章指出，磁盘加密配合安全元件速率限制（10次失败后延迟4小时，15次后延迟41天，仅允许20次尝试）构成核心防线，安全元件还具备内部攻击抵抗能力，防止政府通过强制固件更新绕过限制。GrapheneOS将密码长度上限从16提升至128，支持高熵骰子密码短语，并引入可选的双因素指纹PIN（将指纹尝试次数从20降至5）。此外，文章还涵盖硬件内存标记（MTE）、默认阻止锁定状态下的USB连接、自动重启定时器（默认18小时）将设备恢复到首次解锁前状态，以及胁迫PIN/密码功能——在任何配置文件提示中输入该密码即可立即擦除设备。文章强调这些措施共同构成对物理访问攻击的全面防护。

**评论要点**:

这段讨论涉及多个技术话题，观点分歧明显。关于自托管服务，有评论指出家庭环境缺乏数据中心级的冗余和远程管理能力，一次简单故障或断电就可能导致服务中断，除非有人能随时到场处理；而托管数据中心则具备专业维护和冗余保障。另一部分讨论聚焦安卓应用API级别，认为不更新API往往是为了规避新版安全限制，而非单纯放弃维护，建议在安装时更醒目地提示风险。

在数据备份方面，分歧尤为突出：一方强调完整镜像备份的必要性，指出应用商店下载恢复无法保留依赖旧版32位应用或需服务器激活的软件，可能导致昂贵设备失效；另一方则指出当前技术难以实现真正的全盘镜像，且隐藏卷或加密方案存在漏洞，如Windows会生成临时副本、UEFI下隐藏系统难以实现。整体上，评论者既担忧技术局限性，也质疑现有方案的可靠性与安全性。

## Vercel 的 Scriptc：TypeScript 到原生编译器，二进制中不含 JavaScript 引擎

**描述**:

Vercel Labs 开源了 scriptc，一个将普通 TypeScript 编译为原生可执行文件的编译器，生成的二进制不包含 Node、V8 或任何 JavaScript 引擎，启动约 2.4ms，体积约 178KB。它通过 tsc 解析与类型检查、降级为类型化 IR、再经 LLVM 或 C 后端生成原生代码，静态编译覆盖语言与标准库的大部分特性，无法静态化的部分可用 --dynamic 模式嵌入 quickjs-ng 引擎执行，其余则给出明确错误码。项目通过 800 余个差分测试（与 Node 逐字节比对输出）和 AddressSanitizer 内存安全检测保证正确性，并支持 npm 依赖、Node API、fetch 及原生 FFI 等能力。

**评论要点**:

评论中，一方强调工具目前并不存在，仅属中长期愿景，并指出其架构基于“特性”隔离单元，通过统一接口调用，因此转换工具复杂度被大幅降低。另一方则反对模糊定义，主张直接引用剑桥词典对“工程”的明确解释，认为无需自创宽泛概念。此外，有观点澄清JavaScript虽常被简称为“解释型”，但实际采用JIT编译，应视为“解释或运行时编译”的统称。分歧主要在于对工具现状的认知、定义方式的严谨性，以及技术术语表述的精确性。

## 设计即妥协

Design is compromise

**发布时间**: 2026-07-26

**链接**: [https://stephango.com/design-is-compromise](https://stephango.com/design-is-compromise)

**描述**:
