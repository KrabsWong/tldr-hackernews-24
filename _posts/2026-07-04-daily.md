## 瑞士为何有25Gbps互联网而美国没有

Why Switzerland has 25 gbit internet and America doesn't

**发布时间**: 2026-07-03

**链接**: [https://stefan.schueller.net/posts/the-free-market-lie/](https://stefan.schueller.net/posts/the-free-market-lie/)

**描述**:

瑞士拥有全球最快的25 Gbit对称光纤宽带，价格合理且竞争充分，而美国和德国却落后。其根本原因在于对“自然垄断”的认知差异：光纤网络类似水管，重复铺设是浪费。瑞士通过强监管和政府支持，将光纤作为共享基础设施，多家服务商在同一网络上公平竞争，从而实现高速、低价、选择多样。相反，美国迷信自由市场，允许各公司各自挖路铺网，导致垄断和共享带宽；德国虽多监管，但鼓励地方国企等基础设施建设竞争而非共享，同样造成重复建设和低效。结论：问题的关键不是自由市场或监管的多少，而是是否将物理网络作为开放共享的公共设施，让服务层面的竞争真正发挥作用。

**评论要点**:

该评论主要批评原文缺乏数据支撑，并指出其几处不准确：1) 用Speedtest数据反驳“瑞士网速快且价优”的观点，显示美国固定宽带中位数（306.86 Mbps）略高于瑞士（300.70），移动美国（205.71）远高于瑞士（118.93），25 Gbit并非普通用户常用；价格上美国100 Mbps套餐略便宜但差异可忽略。2) 瑞士FTTP覆盖率仅50%（欧洲69%），农村仅27%（欧洲58%），并非“每户独享光纤”。3) 美国宽带市场并非自由市场，受地方政府特许经营、特许费、市镇宽带禁令、中国设备关税等限制。此外，评论另一部分指出不应将公司拟人化（贪婪是情感，公司只是自动机），并建议如果认为公司能做得更好，应自己创业或认清监管俘获才是症结。

Alibaba to ban Claude Code in workplace over alleged backdoor risks, source says

**链接**: [https://www.reuters.com/world/china/alibaba-ban-claude-code-workplace-over-alleged-backdoor-risks-source-says-2026-07-03/](https://www.reuters.com/world/china/alibaba-ban-claude-code-workplace-over-alleged-backdoor-risks-source-says-2026-07-03/)

**描述**:

阿里巴巴（Alibaba）禁止员工在工作场所使用Anthropic的Claude Code编程工具，原因是该工具被发现可识别中国用户特征，引发安全担忧。此举正值Anthropic指控阿里巴巴“非法提取”其Claude AI模型能力之后，凸显中美在人工智能领域的激烈竞争。尽管Anthropic限制中国用户使用Claude Code，但该工具在中国程序员中仍受欢迎。Alibaba已要求员工转用自家编程平台Qoder。Anthropic此前称阿里巴巴进行了“蒸馏”攻击，即用较弱模型从较强模型输出中学习，以加速提升AI能力。Claude Code内部机制会检查用户时区和代理信息，并向服务器发送标记，Anthropic称这是为防止账户滥用和模型蒸馏的实验。有分析指出，针对中国的限制难以在个人层面执行，但企业更注重法律合规风险。中国AI企业正转向国产及开源模型，同时中国AI模型也在美国市场渗透。该禁令已获中国媒体报道确认。

**评论要点**:

该评论核心观点认为，大语言模型（LLM）训练不侵犯版权，符合美国“公平使用”原则。作者引用四要素测试：第一，LLM通过生成新内容显著推动了知识与艺术进步；第三，训练时使用受版权保护作品，但输出中极少直接复制，属于少量使用；第四，版权所有者并未因LLM丧失获利能力，反而可能借助LLM提高自身产出。因此，LLM训练属于合理使用，误解版权法才会主张侵权。

## 面向网页开发者的 Safari MCP 服务器

The Safari MCP server for web developers

**发布时间**: 2026-07-03

**链接**: [https://webkit.org/blog/18136/introducing-the-safari-mcp-server-for-web-developers/](https://webkit.org/blog/18136/introducing-the-safari-mcp-server-for-web-developers/)

**描述**:

Safari Technology Preview 247 引入了 Safari MCP 服务器，这是一个基于模型上下文协议（MCP）的服务器，旨在提升 web 开发者的调试效率。通过将 AI 代理连接到 Safari 浏览器窗口，代理可以实时获取真实渲染信息（如 DOM、网络请求、截图、控制台输出等），从而实现更自主的调试。用户可以在终端中直接与代理协作，减少窗口切换和反复提示的繁琐流程。

该服务器支持多种用例：在 Safari 中直接开发并检查渲染效果；测试跨浏览器兼容性；分析性能（如导航时间和资源加载）；检查可访问性问题（如缺失标签、ARIA 属性错误、对比度不足）；验证页面状态（如表单、元素、交互流程）。提供的工具包括获取控制台消息、处理浏览器对话框、管理标签页、执行 JavaScript、详细网络请求分析、页面内容提取等。

Safari MCP 服务器简化了调试工作流，使代理能更高效地发现问题并修复，从而改善产品质量和用户体验。未来还将支持更多功能。

**评论要点**:

Playwright 的主要优势是跨浏览器支持（如 Chrome、Firefox、Safari），常用于自动化测试和一次性任务（利用 CDP 技巧）。与其他工具相比，Playwright 在 Web 开发中能跨浏览器工作，但浏览器特定工具可能速度更快或 token 效率更高，更适合任务自动化和爬虫。微软推荐 CLI 方式配合编码代理（如 Claude Code、GitHub Copilot），因为 CLI 命令可避免加载大型工具模式和冗长的无障碍树，节省 token 上下文；但对于长时间运行的自主任务（如 UAT 代理），仍建议使用 MCP 方案。
