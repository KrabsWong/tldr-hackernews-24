## Cloudflare收购Deno

Cloudflare acquires Deno

**发布时间**: 2026-10-09

**链接**: [https://deno.com/blog/cloudflare](https://deno.com/blog/cloudflare)

**描述**:

Deno 团队宣布整体加入 Cloudflare，未来开发将聚焦于基于 Cloudflare Workers 编程模型的共享平台，而非继续开发独立的运行时和托管服务。Deno 运行时将在一年内继续提供每月修复和安全更新，之后停止开发但保持开源；Deno Deploy 将在六个月后关停，付费客户可迁移至 Cloudflare Workers；JSR 继续运营并将基础设施迁至 Cloudflare，同时继续支持 rusty\_v8 并推动其集成到 workerd。

**评论要点**:

有人认为 Deno 若直接接受付费或捐赠，本可轻松获得成千上万的付费用户，但它却选择追逐风投，这是战略上的失误。另一些人则认同 Deno 品质出色，不该就此消亡。同时也有质疑声音：Node.js 或 Bun 究竟哪里不好，为何非要选择 Deno？

**链接**: [https://iminafleeting.com/](https://iminafleeting.com/)

**描述**:

## Hetzner云网络栈——历史与技术概览

The Hetzner Cloud network stack – history and technical overview

**发布时间**: 2026-10-09

**描述**:

Hetzner Cloud 的网络栈经历了从早期 Linux 网桥与静态路由，到 BGP 动态路由，再到 2019 年引入基于 Open vSwitch 的数据平面并支持 VXLAN 私有网络的演进。当前架构将防火墙、私有网络、DHCP 和元数据服务等网络功能放在虚拟机宿主机上运行，物理网络仅提供稳定的 IP 连通性。为编排 Open vSwitch 流，团队自研了 Python 编写的 Flusskrebs 控制器，并通过 ctcount 限制每台服务器最多 8 万条并发连接。该栈已支撑超过一百万台云服务器，但已触及扩展性等限制，后续将推出全新自研网络栈。

**评论要点**:

有人希望Hetzner能把独立服务器业务拓展到美国，认为其数据中心运营能力出色。另有人称赞Hetzner性价比高，并正在其基础上搭建一个开源的“自建Vercel”服务，欢迎反馈。还有人分享经验称，旧版Restic搭配Hetzner时速度很慢，升级到最新稳定版后因SSH缓冲机制改善，速度提升了十倍。
