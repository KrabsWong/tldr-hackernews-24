## Java 很快，但代码未必

Java is fast, code might not be

**发布时间**: 2026-03-20 13:43

**链接**: [https://jvogel.me/posts/2026/java-is-fast-your-code-might-not-be/](https://jvogel.me/posts/2026/java-is-fast-your-code-might-not-be/)

**描述**:

文章指出Java本身性能优异，但开发者常因代码中的反模式导致性能低下。作者通过优化一个订单处理应用，将处理时间从1198毫秒降至239毫秒，吞吐量提升至5倍，堆内存减少87%，GC暂停减少79%。文中列举了八个常见性能陷阱：在循环中进行字符串拼接、流操作导致O(n²)复杂度、在热点路径使用String.format()、自动装箱、用异常控制流程、同步锁范围过大、重复创建可重用对象（如ObjectMapper）以及虚拟线程在JDK 21-23中的线程固定问题。这些模式在单独或低频使用时无害，但一旦位于热点路径，会显著拖累性能并增加资源消耗。优化关键在于结合性能剖析数据识别并修复这些模式，其效果在规模化部署中尤为显著。

**评论要点**:

关于ORM的讨论指出，即使使用ORM，开发者仍常额外创建数据库包装层，这被视为不必要的抽象。在内存优化方面，多数评论者反对简单采用对象池解决内存压力，认为应先通过性能分析（如JFR和堆转储）定位根本原因。常见优化策略包括：减少不必要的分配，如使用流（streams）合并操作、改用原始类型、避免自动装箱，或在特定情况下使用对象缓存（如Map.computeIfAbsent）。争议点在于是否应依赖语言特性（如Valhalla项目）或重构代码逻辑，共识是避免重新实现垃圾回收机制，而应专注于消除分配源头。
