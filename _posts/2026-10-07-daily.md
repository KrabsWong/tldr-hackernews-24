## 在Chrome中支持JPEG XL

Shipping JPEG XL in Chrome

**发布时间**: 2026-10-07

**链接**: [https://developer.chrome.com/blog/jpeg-xl-in-chrome](https://developer.chrome.com/blog/jpeg-xl-in-chrome)

**描述**:

Chrome 从 155 版本开始支持 JPEG XL（\.jxl）图像格式的解码。该格式相比 JPEG 压缩率提升 30\-50%，支持无损压缩、HDR 和无损 JPEG 转码，官方建议与 AVIF 一并尝试。为提升内存安全，Chrome 采用纯 Rust 实现的解码器 jxl\-rs，并通过 SIMD 抽象层保持性能，经模糊测试和 AI 代码审查未发现内存安全漏洞。

**评论要点**:

Navier–Stokes Lost in Translation

**发布时间**: 2026-10-07

**链接**: [https://arxiv.org/abs/2610.08144](https://arxiv.org/abs/2610.08144)

**描述**:

该论文指出，自动形式化被越来越多地用于验证数学文本，包括AI生成的证明，例如OpenAI宣布的Navier\-Stokes方程解爆破证明。作者论证，由于自然语言数学文本存在歧义，实现语义忠实翻译的问题在可解复杂性指数（SCI）层级中任意高（SCI为无穷），因此语义忠实的AI自动形式化比包括停机问题在内的任何计算问题都更难。文中给出了多个AI将自然语言陈述和证明误译为Lean的实例，导致自然语言证明与其Lean“验证”不匹配，其中包括OpenAI宣布的Navier\-Stokes证明，其形式化Lean证明与自然语言爆破证明并不对应。

**评论要点**:

有人认为，先在Lean中构思证明是可行的，甚至比作猴子更贴切；也有人指出，Codex Astra在形式化时常常完全依赖Lean。分歧在于，质疑者强调真正值得追问的是证明的生成方法，而非工具本身，并批评相关方借“神奇产品”完成证明来推销其能力。

**描述**:

文章列举了软件博客写作中常见的反模式，包括开头冗长绕弯、假设读者具备与作者相同的背景知识、过度依赖链接解释术语、在文章开头就要求读者读过前作、行文过于正式，以及在移动端页面溢出和字体对比度不足等基础渲染问题。作者建议在标题和前三句话内给出读者继续阅读的理由，尽量减少对读者知识背景的假设，用最少解释替代链接跳转，让文章可独立阅读，以口语化风格写作，并在发布前用浏览器移动预览检查排版与可读性。

## Docker代理

**描述**:

Docker Agent 是 Docker Engineering 推出的 AI 智能体构建与运行时工具，作为 docker CLI 插件可通过 docker agent 命令使用。它支持用声明式 YAML 配置定义智能体，具备多智能体协作、丰富的工具生态（内置工具及任意 MCP 服务器）、兼容多种 AI 提供商以及 RAG 检索等特性。用户可通过 Docker Desktop、Homebrew 或二进制发布安装，并能将智能体推送到任意 OCI 仓库进行分享和运行。

## 像1866年那样写作：大型语言模型重新学习电报文体

Write Like It's 1866: LLMs Relearn Telegraphese

**发布时间**: 2026-10-07

**链接**: [https://fiveminutesforward.com/post/2026-10-04-telegraph-test/](https://fiveminutesforward.com/post/2026-10-04-telegraph-test/)

**描述**:

文章介绍了一项名为“Telegraph Test”的基准测试，借鉴1866年电报按词计费时代的两类压缩策略：代码本替换和“cablese”电报文体。测试显示，让模型用cablese写记录可节省约40%至49%的token，而其他模型家族在冷启动阅读这些压缩记录时，答题准确率与纯文本相当甚至略高（恢复比0\.99至1\.10）。不过压缩若发生在模型仍在生成答案时会产生准确率损失，且对无法关闭推理的模型（如gpt\-5\-mini）反而使成本翻倍。作者认为cablese适合用于机器消费的中间文本，如草稿、记忆存储和智能体间传递，并强调其可读、可审计，区别于自发涌现但不可读的压缩协议。

**评论要点**:

评论认为原文虽有想法，但写作需要改进：标点不一致、句子过于隐晦、压缩过度导致读者难以还原语境，且“elicit”等用词不当，并给出改写建议，主张首句应更明确。分歧在于，一方强调写作成功标准比代码运行更复杂、需顾及读者理解，另一方则补充了相关模型发布信息，并提出智能体可通过摩尔斯电码、端口敲门或路由表等方式通信。
