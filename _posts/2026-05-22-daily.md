## Flipper One——我们需要你的帮助

Flipper One – we need your help

**发布时间**: 2026-05-21

**链接**: [https://blog.flipper.net/flipper-one-we-need-your-help/](https://blog.flipper.net/flipper-one-we-need-your-help/)

**描述**:

Flipper One 是一个全新的开源Linux硬件平台，不同于Flipper Zero（专注于低层点对点协议），它面向IP网络层，支持PCIe、USB 3.0、SATA等高速扩展，可集成5G、SDR、AI等功能。团队设定了雄心勃勃的目标：打造最开放、文档最完善的ARM计算机，完全支持主线Linux内核，摒弃闭源二进制包和厂商锁定的BSP，并与Collabora合作将Rockchip RK3576 SoC推入主线。项目历经多年，技术及财务挑战巨大，因此团队公开寻求社区帮助，希望共同推动开源与教育。

**评论要点**:

第一段评论强调高频信号分析（如1.6GHz RAM、16GHz PCIe）需要价值超50万美元的屏蔽实验室和专用设备，且具备该能力的RF工程师极为稀缺，被视为“黑暗艺术”。  
第二段评论认为文章中的重复说明并非缺点，而是故意为之的消费者教育，类似风格在《纽约客》等出版物中常被称赞；作者通过反复阐述Flipper One与Flipper Zero的区别，帮助读者理解产品层级。  
第三段评论指出Rockchip Linux内核的源码虽然以未合并的6.6内核分支形式存在，但问题在于该分支尚未整合到主线。

## 在对话中抛出AI生成的文本墙

Throwing AI-generated walls of text into conversations

**发布时间**: 2026-05-21

**链接**: [https://noslopgrenade.com/](https://noslopgrenade.com/)

**描述**:

文章反对在聊天或邮件中粘贴大段AI生成文本的行为，称之为“slop grenade”（垃圾手榴弹）。这种行为用一个句子就能回答的问题，却抛出长篇AI分析，破坏沟通本质：接收者无法回应，对话被扼杀，时间被浪费。作者主张使用AI应使内容更清晰、更简短，而非更长；要保留人类判断和简洁交流。受nohello.net启发，呼吁用人类的方式沟通。

**评论要点**:

该评论的核心观点有三：第一，多数情况下人们询问AI是因为需要真实意见或无法通过AI找到信息，但AI常给出未经核实的冗长错误答案，而非坦诚说“不知道”，导致提问者无法快速转向可能知晓答案的人。第二，批评将“tech”一词过度泛化，认为应明确指代“计算机”或“软件”，而非滥用指代所有技术（如火、轮子）。第三，指出“大量文本往往信息量少”并非新常态，而是意在营造工作量大的假象；这种“咨询顾问思维”在AI出现前已存在，而AI进一步恶化了这一趋势。

**描述**:

西雅图警方运营着一个名为“Seattle Shield”的私密情报共享网络，成员包括Facebook、亚马逊、ICE、FBI等私营企业和政府机构。该网络自2009年起运作，旨在通过公私合作防范恐怖主义，但缺乏问责制和透明度。Prism通过公共记录获取了2020年成员名单及2020-2025年间的大量简报，发现2025年的报告几乎全部聚焦于抗议活动和交通延误，例如针对哈马斯袭击周年纪念的预警。长期关注该网络的隐私活动人士Phil Mocek警告，结合特朗普总统2025年将抗议言论列为恐怖威胁指标的国家安全备忘录，Seattle Shield共享的信息可能轻易将抗议者标记为“极左国内恐怖分子”。文章质疑该网络的实际效用，并指出其运作几乎未受到主要民权组织的关注。

**评论要点**:

## Python 3.15：未上头条的功能

Python 3.15: features that didn't make the headlines

**发布时间**: 2026-05-21

**链接**: [https://blog.changs.co.uk/python-315-features-that-didnt-make-the-headlines.html](https://blog.changs.co.uk/python-315-features-that-didnt-make-the-headlines.html)

**描述**:

Python 3.15 带来了一些未引起广泛关注但实用的新特性。首先，`asyncio.TaskGroup` 新增 `cancel()` 方法，允许优雅地取消任务组而无需抛出异常，简化了中断后台任务的流程。其次，上下文管理器作为装饰器（`@contextmanager`）的用法得到改进，`ContextDecorator` 现在能正确处理异步函数、生成器和异步迭代器，确保装饰器覆盖完整生命周期，避免了常见陷阱，使上下文管理器成为创建装饰器的更佳选择。此外，还引入了线程安全迭代器（Thread Safe Iterators），但文章未提供详细说明。这些特性提升了 Python 的可用性和开发效率。

**评论要点**:

评论核心观点：在DOS和Windows（不包括C/C++）环境中，不区分大小写是标准行为，开发者曾认为区分大小写是反常的。不同语言有不同的抽象层级：C需要手动控制内存，能榨取极致性能但开发困难；Python更易用但性能受限。程序员和项目常从易用语言起步以提升开发速度，随后转向更困难的语言以获取更高性能，这是从原型到生产的常见演进路径。最后提及VB也采用不区分大小写的名称解析。核心思想是性能与开发效率的权衡决定了语言选择。

## 1945年三位一体核试验丢失影像修复

Lost Images from the 1945 Trinity Nuclear Test Restored

**发布时间**: 2026-05-21

**链接**: [https://spectrum.ieee.org/trinity-nuclear-test](https://spectrum.ieee.org/trinity-nuclear-test)

**描述**:

文章介绍了1945年7月16日“三位一体”核试验的珍贵历史照片被重新修复并公开。摄影师伯林·布里克纳在距爆心200米的掩体中，使用高速摄像机拍摄了爆炸瞬间的火球。尽管52台相机中仅11台成功成像，但通过多角度、多帧率的布置，科学家得以精确测量核爆效果。照片记录了爆炸后不到百分之一秒内，炽热能量球撕裂黑暗的瞬间，以及随后升腾的多彩火云。这些影像为研究核爆炸的物理效应提供了关键数据。同时，文章提到陆军中士赫伯特·莱尔于7月12日将钚核心运至装配地点。这些修复后的图像首次以极高清晰度展现了人类进入核时代的决定性时刻。

**评论要点**:

## FatGid：FreeBSD 14.x 内核本地权限提升

FatGid: FreeBSD 14.x kernel local privilege escalation

**发布时间**: 2026-05-21

**链接**: [https://fatgid.io/](https://fatgid.io/)

**描述**:

FreeBSD 14.x 内核 `setcred(2)` 系统调用中存在栈缓冲区溢出漏洞（CVE 未明确），源于 `kern_setcred_copyin_supp_groups()` 中 `sizeof(*groups)` 的错误使用（本应为 `sizeof(gid_t)=4`，实际为 `sizeof(gid_t *)=8`），导致最大可溢出 60 字节。该溢出发生在权限检查之前，任何非特权本地用户均可触发，可实现内核崩溃或完全本地提权（LPE），且在启用 SMAP/SMEP 的情况下仍可利用（依赖于 ZFS 内核模块）。该漏洞影响 FreeBSD 14.3、14.4 和 15.0（15.0 仅可导致崩溃，未实现提权）。官方于 2026-05-21 发布安全公告 FreeBSD-SA-26:18.setcred，已在 14.3-RELEASE-p14、14.4-RELEASE-p5、15.0-RELEASE-p9 及更早的 stable 分支中修复。用户应及时更新。

**评论要点**:

用户仅关注安全列表中的漏洞是否已修复，并希望更新日志中明确标注，不需要任何宣传或炒作。此外，有用户发布了关于某bug的模糊截图，尚待详细说明。最后，用户对软件生态逐渐向Linux单极化发展表示遗憾。
