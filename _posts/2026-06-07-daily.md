## 超越 fork() + exec()

Moving beyond fork() + exec()

**发布时间**: 2026-06-06

**链接**: [https://lwn.net/SubscriberLink/1076018/16f01bbbb8e0d1f0/](https://lwn.net/SubscriberLink/1076018/16f01bbbb8e0d1f0/)

**描述**:

文章讨论了Linux内核中传统的 `fork()` + `exec()` 进程创建模式的低效问题，指出 `fork()` 需要复制整个进程状态，而紧接着的 `exec()` 会丢弃这些复制内容，造成不必要的开销。开发者Li Chen提出了“spawn templates”（生成模板）的补丁方案，旨在通过缓存可执行文件信息来加速重复启动同一程序的过程。该方案引入了两个系统调用：`spawn_template_create()` 创建代表可执行文件的模板文件描述符，以及 `spawn_template_spawn()` 指定每次调用的参数（如argv、envp、文件描述符操作）进行快速启动。虽然该补丁当前未被接受，但它可能为未来更高效的进程创建原语提供方向。

**评论要点**:

评论核心观点：zygote（预派生）模式存在局限，其关键难点在于无法在代码任意位置注入fork调用，必须提前规划，在程序启动初期、无线程、无打开文件、无锁时执行，否则会引发安全问题。虽然zygote初衷是提高效率，但更安全的替代方案是通过特殊API实现，然而由于已普遍使用fork，需求不足。此外，评论指出重复创建和销毁进程（如为每个任务启动独立进程）资源开销大，使用nginx风格的进程池（保持固定数量进程复用）通常更高效。同时提及launchd和systemd等系统服务管理器刻意减少shell参与启动过程，以避免影响启动速度和引入不确定性。

*[HackerNews](https://news.ycombinator.com/item?id=48425528)*

## Zeroserve：一个可用eBPF脚本化的零配置Web服务器

Zeroserve: A zero-config web server you can script with eBPF

**发布时间**: 2026-06-06

**链接**: [https://su3.io/posts/introducing-zeroserve](https://su3.io/posts/introducing-zeroserve)

**描述**:

zeroserve 是一个零配置的 HTTPS 服务器，以单个 tarball 形式提供网站服务，支持 HTTP/2、TLS 1.3 和热重载。其核心创新是用 eBPF 程序替代传统配置文件：将 eBPF 脚本置于 tarball 的 `.zeroserve/scripts/` 目录下，运行时在用户空间 JIT 编译为原生代码，作为沙盒中间件处理每个请求，实现路由、认证、限流、反向代理等功能。所有 I/O 通过 io_uring 执行，单线程事件循环模型，部署只需原子替换 tarball 并发送 SIGHUP。相比 nginx 和 Caddy，它将声明式配置与脚本层合并为一个可从上到下阅读的 eBPF 程序，旨在简化运维并提升性能。

**评论要点**:

**描述**:

本文介绍了一个名为“Azure Linux Desktop”的Windows玩具应用，它能在窗口中启动完整的Linux桌面环境。该应用利用了微软Build 2026发布的四项技术：wslc（新的原生Linux容器运行时）、WinUI Reactor（无XAML的C# UI框架）、Azure Linux 4.0（基于Fedora 43的服务器发行版）和.NET 10。启动后，应用先显示引导界面，然后通过wslc API加载并运行一个包含XFCE桌面的容器，并通过XRDP和Windows内置RDP客户端实现显示、音频、GPU加速和剪贴板共享。作者强调这只是一个实验性项目，依赖未稳定组件（如从WSL主分支编译的wslc），将Fedora桌面包强行塞入服务器发行版，并使用了早期版本的WinUI Reactor。源码已开源在GitHub上。

评论核心观点：批评“tuned”一词的误用。作者认为通用操作系统应能承载任意上层应用栈，而非为特定场景优化（如Windows Datacenter仅用于虚拟机，IoT Core仅用于嵌入式）。而“tuned”应指对底层硬件适配（如手机OEM的Android定制）——这类调优仍保留通用性，用户可在其上运行任意Android软件。与此相反，工业垂直定制（如车载Android）因剥离通用框架而丧失通用性。举例：Azure Linux和单板计算机的Linux“调优”类似手机OEM调优，仍保持通用性，仅针对特定硬件提升性能，不限制上层应用。核心区分：调优（硬件适配）≠专用化（限制用途）。
