I found 10k GitHub repositories distributing Trojan malware

**发布时间**: 2026-06-18

**链接**: [https://orchidfiles.com/github-repositories-distributing-malware/](https://orchidfiles.com/github-repositories-distributing-malware/)

**描述**:

作者在GitHub上发现约10,000个仓库通过特定模式分发木马恶意软件。这些仓库非fork，但共享特征：每几小时删除旧提交，仅更新readme添加zip链接，提交内容从其他仓库复制。通过gharchive分析过去5天的16百万次提交，筛选出约3000个频繁更新的可疑仓库。进一步检查发现zip包含loader.exe、lua51.dll等文件，VirusTotal检测出木马。作者向GitHub举报后，部分仓库被移除。

**评论要点**:

评论核心观点：部分用户认为，要完善某个项目，开发者需要更改二进制文件并使用微软启动器捆绑软件，但具体含义不明。另有用户指出类似案例，并附上关于GitHub上上千个游戏模组和破解软件窃取数据的调查链接，暗示当前讨论可能与安全风险或恶意捆绑相关。摘要需聚焦于对现有模式的质疑及引用已发现的真实案例。

## .gitignore 不是忽略文件的唯一方式

.gitignore Isn't the only way to ignore files in Git

**发布时间**: 2026-06-18

**链接**: [https://nelson.cloud/.gitignore-isnt-the-only-way-to-ignore-files-in-git/](https://nelson.cloud/.gitignore-isnt-the-only-way-to-ignore-files-in-git/)

**描述**:

Git 中除了 `.gitignore`，还有两种忽略文件的方式：`.git/info/exclude`（位于仓库 `.git` 目录内，不提交到 Git，适合单仓库个性化忽略）和 `~/.config/git/ignore`（全局机器级别，忽略所有仓库中的指定文件，如 macOS 的 `.DS_Store`）。可通过 `git config --global core.excludesFile` 自定义全局忽略文件。使用 `git check-ignore -v <文件名>` 可查看文件被哪个忽略文件所忽略。这些方法实现了从项目、本地仓库到全局机器的三级忽略机制。

**评论要点**:

该评论有两个核心观点：1）作者发现新Mac预装了~/.gitignore_global文件，内含.DS_Store条目，且全局git配置已忽略此文件，认为未来可能无需手动添加.DS_Store到.gitignore；2）作者强调检查uv.lock等依赖锁定文件的diff很重要，不应盲目升级所有依赖，需了解直接或传递依赖的更新情况。
