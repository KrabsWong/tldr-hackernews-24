**描述**:

屏幕无法显示某些真实世界中的颜色，尤其是高饱和度的青色。这是因为人眼有三种视锥细胞，它们对光波长的响应不同，但只能报告“音量”而非具体波长。任何能同样刺激这三种细胞的混合光看起来颜色相同。1931年CIE色度图绘制了所有人眼可见的颜色，但基于红绿蓝三原色的屏幕只能覆盖其三角形区域，导致大量青色/蓝绿色被排除在外。要再现这些颜色需要负值的红色光，这在现实中无法实现。文章介绍如何通过真实世界中的物体（如某些颜料、荧光或自然光）找到这些屏幕无法呈现的青色。

1. 一位用户称赞"C-800 Spectromaster"这种专业设备的命名方式非常恰当。

## 将网站存储于Favicon中

I Stored a Website in a Favicon

**发布时间**: 2026-06-20

**链接**: [https://www.timwehrle.de/blog/i-stored-a-website-in-a-favicon/](https://www.timwehrle.de/blog/i-stored-a-website-in-a-favicon/)

**描述**:

作者尝试将一个小型网站存储在浏览器标签页的 favicon 中。他将 HTML 文本（208 字节）转换为 UTF-8 字节，添加 4 字节长度头，然后逐像素写入 RGB 通道，生成一个 9×9 像素的 PNG 图像作为 favicon。加载页面时，JavaScript 通过 Canvas 读取 favicon 像素，反向解码得到原始 HTML 并替换页面内容。虽然容量极小且需要引导脚本，但展示了将数据隐藏在意想不到位置的可能性。这种技术实用性低，但富有探索趣味。

**评论要点**:

评论核心观点：1）用户对Medium上某种写作风格提出质疑，但作者解释称这是针对小手机屏幕阅读的优化风格，用户觉得有道理，但不确定文章是否为AI生成；2）另一用户表示完全赞同；3）有用户指出AI检测工具Pangram不可信，因为它曾将多篇纯人工撰写的文章误判为“高概率LLM生成”。整体上，评论聚焦于写作风格适配设备、AI生成内容的辨识难度以及检测工具的可靠性问题。

## 卫星揭示GPS信号干扰规模惊人

Satellite reveals immense scale of GPS signal tampering

**发布时间**: 2026-06-20

**链接**: [https://www.space.com/space-exploration/satellites/its-quite-a-bit-more-than-we-expected-satellite-reveals-immense-scale-of-gps-signal-tampering](https://www.space.com/space-exploration/satellites/its-quite-a-bit-more-than-we-expected-satellite-reveals-immense-scale-of-gps-signal-tampering)

**描述**:

一项实验性卫星首次从太空测绘了欧洲和中东地区GPS信号干扰的规模，结果远超预期。该卫星名为Pulsar-0，属于美国Xona空间系统公司的新型导航星座，目前正在低地球轨道测试。其携带的GPS接收器发现，在欧洲和中东部分区域，信号强度从正常的40分贝骤降至10分贝。从法国到巴基斯坦边境，低地球轨道卫星普遍受到信号干扰，这揭示了GPS干扰问题的严重性。由于现有全球导航卫星系统信号较弱，易被压制或欺骗，而Xona计划部署300颗更强信号的卫星以提供更抗干扰的服务。

**评论要点**:

## 大语言模型现已复杂

LLMs Are Complicated Now

**发布时间**: 2026-06-20

**链接**: [https://ianbarber.blog/2026/06/19/llms-are-complicated-now/](https://ianbarber.blog/2026/06/19/llms-are-complicated-now/)

**描述**:

大型语言模型（LLM）的架构已从2022-2023年简洁的Transformer堆叠，演变为如今高度复杂的系统，类似推荐系统的发展路径。现代模型引入了多种注意力变体（分组、压缩、稀疏、滑动窗口等）、混合专家（MoE）路由、多模态编码器混合，以及跨GPU推理带来的通信操作。这种复杂性源于持续提升能力与保持推理效率之间的张力。虽然人们寄望于智能代理自动优化内核（如生成融合算子），但实际中，性能从“优化”变为“必需”的差距极小——在没有可验证基线的情况下，无法冒险探索效率低一个数量级的变体。因此，研究人员需要像PyTorch的FlexAttention那样，在设计之初就追求可组合性与可验证性，通过模板生成内核，在保证效率的同时支持灵活探索。最终，构建可组合的架构比单纯依赖自动化循环更为关键。

**评论要点**:

评论核心观点：原父评论是AI生成的废话，却意外引发热烈讨论。说话者自90年代起习惯用连字符代替长破折号，因此真正的em dash反而成为AI写作的破绽。同时认同多数指责AI痕迹的人实际也在使用AI。最后引申到“熵增”的哲学隐喻，暗示混沌与复杂性终将主导一切。

## Linux经六年与360个补丁后移除Strncpy API

Linux Eliminates the Strncpy API After Six Years of Work, 360 Patches

**发布时间**: 2026-06-20

**链接**: [https://www.phoronix.com/news/Linux-7.2-Drops-strncpy](https://www.phoronix.com/news/Linux-7.2-Drops-strncpy)

**描述**:

Linux 内核在 7.2 版本中彻底移除了长期被弃用的 strncpy API。这项工作历时六年，共提交了超过 362 个补丁。strncpy 因其反直觉的语义、NUL 终止问题及冗余清零导致的性能缺陷，一直是内核中持续的 bug 来源。开发者应采用 strscpy()、strscpy_pad()、strtomem_pad()、memcpy_and_pad() 或 memcpy() 等更安全的替代函数。

**评论要点**:

AI训练数据包含大量有bug的C代码，且这些错误常未被标记，因此AI生成的代码难以避免人类曾犯的错。NULL概念本身无问题，但无法声明“非空”类型导致大量安全漏洞（如CVE），现代语言（Python、TypeScript、Java）已通过可选性和非空类型解决此问题。Linux内核曾使用strlcpy函数，20年后因接口设计更优而被strscpy取代（详见2022年LWN文章）。
