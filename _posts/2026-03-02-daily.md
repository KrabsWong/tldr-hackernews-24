## MCP 与 CLI 相比，何时更有意义？

When does MCP make sense vs CLI?

**发布时间**: 2026-03-01 16:54

**链接**: [https://ejholmes.github.io/2026/02/28/mcp-is-dead-long-live-the-cli.html](https://ejholmes.github.io/2026/02/28/mcp-is-dead-long-live-the-cli.html)

**描述**:

作者认为模型上下文协议（MCP）正在式微，因为它并未提供真正的实用价值。大型语言模型本身已擅长使用命令行工具，无需额外协议。相比之下，CLI工具具备显著优势：它们既服务于人类也适用于机器，调试简单（可直接复现命令），工具之间可灵活组合（如管道连接），并且复用现有、成熟的认证体系。MCP则引入了不必要的复杂性，如服务器管理负担、独立的认证流程和权限控制粗糙。因此，除了极少数没有CLI替代品的场景，在绝大多数工作中，CLI是更简单、可靠且高效的选择。

**评论要点**:

评论围绕MCP（Model Context Protocol）的实用性展开。主要共识认为，对于生产环境和构建可扩展应用，应优先使用声明式API；而CLI更适合探索、学习和新项目开发。反对MCP的观点认为它是无用的抽象层，不如直接使用CLI工具和技能，理由包括MCP消耗过多上下文token且成本高。支持者则指出，通过优化指令（如使用CLAUDE.md）和利用Shell中高度可组合的工具，能显著减少token使用并提升LLM（如Claude）的工作效率。关键替代方案强调用精准指令配合轻量级工具替代MCP服务器，以实现更高效的AI工作流。
