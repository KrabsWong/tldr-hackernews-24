## Cursor市场上VS Code扩展的Claude Code后门

Backdoor in Claude Code for VS Code extension on the Cursor Marketplace

**发布时间**: 2026-10-30

**链接**: [https://phorion.io/blog/offical-claude-code-vsx-compromise/](https://phorion.io/blog/offical-claude-code-vsx-compromise/)

**描述**:

Phorion 发现 Cursor Marketplace 上官方 Claude Code for VS Code 扩展 2\.1\.313 版本被植入后门，扩展包在加载时即执行注入代码，向 \~/\.ssh/authorized\_keys 追加攻击者公钥，并建立到 134\.209\.82\.225 的反向 SSH 隧道，同时在 macOS、Linux、Windows 上设置持久化并回传主机侦察信息。macOS 上因非特权执行 systemsetup \-getremotelogin 返回权限错误而非 Off，启用远程登录的步骤被跳过，但密钥植入和持久化仍会发生。文章建议排查该版本使用情况，清除 LaunchAgent、cron 或计划任务及 \.smt 脚本，移除相关 SSH 密钥并轮换凭据。

**评论要点**:

有人认为，如果根本没有签名封条，就很难说这是恰当的类比；而且事件中并不存在拦截，最多是有人说服思科发货，而思科表示这不是自己的责任，他们确实发运了并非自己制造或检查过的东西。另有人指出，Cursor 市场可能与 VSCode 市场相互独立，问题也许只是有人冒充 Anthropic，因为对方从未在该市场注册，仅靠代码签名无法解决这类情况。还有人提到，团队管理员可以推迟扩展安装和更新，直到市场版本发布满一定小时数，并认为经历此事后大家都会把这一时限设为 168 小时。

## AI并未取代SRE，而是使其技能退化。

AI isn't replacing SREs, it's deskilling them

**发布时间**: 2026-10-30

**链接**: [https://newsletter.signoz.io/p/ai-isnt-replacing-sres-its-deskilling](https://newsletter.signoz.io/p/ai-isnt-replacing-sres-its-deskilling)

**描述**:

文章借1983年Bainbridge的自动化讽刺理论，讨论AI在SRE工作中可能造成的技能退化：AI接管告警降噪、已知问题处置和根因建议等常规任务后，SRE只在罕见复杂故障中介入，反而缺少锻炼直觉的机会。医学与航空领域的研究显示，依赖AI辅助后人的独立判断和手动操作能力会下降，且当事人往往难以察觉。文章还提出“从未习得技能”的问题，即初级SRE在AI主导的环境中难以积累基础经验，并建议刻意保留人工演练、让人类深度参与而非仅做监督。

**评论要点**:

有评论认为，AI处理事故看似5分钟解决，实际常需30分钟应对幻觉和无意义输出，甚至有人把完整输出转交他人解读，自己充当团队与AI间的“人肉代理”；对需快速响应的系统，更应依靠设计阶段的警报、监控和故障保护。另有评论反对“AI等于编译器”的类比，认为小规模下结果接近确定，规模一大AI就不再确定，生成代码可能明显偏离指令。还有评论从内部构建系统角度说明自建构建矩阵、定制gcc编译标志和提前获取CVE修复的价值。

*[HackerNews](https://news.ycombinator.com/item?id=50305693)*

## Azure最薄弱环节——五起完整的跨租户入侵

**发布时间**: 2026-10-30

**链接**: [https://www.binarysecurity.no/posts/2026/10/one-root-case](https://www.binarysecurity.no/posts/2026/10/one-root-case)

**描述**:

文章披露Azure Logic Apps中API Connections架构存在五处跨租户提权漏洞，攻击者可借路径遍历及未公开的DynamicList等端点，利用他人连接访问Key Vault、Azure SQL及Jira、Salesforce等后端服务。作者还发现Consumption Logic App的host\.api\.RuntimeUrl参数可绕过连接归属校验，且修复因路径规范化时序问题被再次绕过。相关漏洞共获约20万美元奖励，均已修复。
