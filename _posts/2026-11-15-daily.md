## 所有AI生成的代码都应开源

All AI-generated code should be Open Source

**发布时间**: 2026-11-15

**链接**: [https://jakub.jankiewicz.org/blog/ai-code-open-source/](https://jakub.jankiewicz.org/blog/ai-code-open-source/)

**描述**:

作者主张所有由AI生成的代码都应开源。理由包括：AI模型训练使用了大量开源代码及采用署名要求的Stack Overflow内容，将其转为专有闭源代码有许可洗白之嫌；纯AI生成代码并非人类创作，按美国版权局及Monkey Selfie先例不应受版权保护。由于各国法律不同，作者建议开发者明确以开源许可证发布AI生成代码，或用CC0贡献至公有领域，尤其针对人类仅写提示、几乎未审查修改的代码。

**评论要点**:

一方认为“人类有史以来全部智力产出作为训练数据”的说法不可能成立，且大量有用文本已属公有领域，无需抓取Reddit回复来理解合理推理。另一方反驳称对方混淆了“inspiration”的词源与法律语境下的定义，强调灵感是借鉴现有主题风格进行原创，侵权则是未经许可过度模仿，并引用词典和法律文章佐证。分歧集中在训练数据范围是否现实，以及“灵感”与“侵权”的界定应依据词源还是法律概念。

**描述**:

美国加州北区联邦法官Noël Wise于11月14日全面驳回三星、SK海力士和美光针对一项拟议集体诉讼的联合撤诉动议，认定起诉书合理主张三家公司违反《谢尔曼法》第一条达成限制传统DRAM供应的协议。法院认为本案不同于第九巡回法院2022年维持驳回的DRAM II案，并指出HBM长期锁定合同、拒绝传统DRAM长期合同、美光关闭Crucial、工厂延期、创纪录价格下不扩产、近乎相同的客户审查做法及三家公司的历史卡特尔记录等，支持存在共谋的合理推断。法院未采纳投资者关于“供应纪律”的表述、行业会议会面及寡头市场结构三项论据。法院要求各公司于2026年12月7日前答辩，首次案件管理会议改期至2027年1月12日。

**发布时间**: 2026-11-15

**链接**: [https://geoffstearns.com/blog/your-agent-will-pick-the-hackable-one/](https://geoffstearns.com/blog/your-agent-will-pick-the-hackable-one/)

**描述**:

文章以约70美元的M\-VAVE FM\-1合成器为例，说明用户自2024年9月起用AI工具为其编写自定义固件，M\-Vave随后以GPLv3开源官方固件并提供开发套件和浏览器模拟器。作者认为，随着AI降低固件开发成本，能更换固件的设备将更受AI代理青睐，从而推动厂商开放；签名固件和锁定引导程序会阻碍这一趋势，而封闭厂商常以安全为由限制接入。作者还指出，关键在于代理服务于用户还是厂商，并建议硬件厂商预设固件会被替换且易于安全回退。

**评论要点**:

多数电视在硬件设计上仍具备一定可维修性，如LG部分型号的计算模块、Wi-Fi模块与屏幕驱动分离，便于拆解维护。分歧在于，有人认为这种可维修性需在提示中明确说明才会被重视，系统默认不会主动考虑硬件可改造性；另有人关注训练数据是否对内容加标识，还是直接混入训练集。

Gawain 是一个 Python 工具，要求为变量、参数、返回值和类属性添加类型注解，随后调用 ty 或 pyrefly 等类型检查器验证类型是否正确。与 ruff 的 ANN 规则和 flake8\-annotations 只要求函数注解不同，Gawain 还要求变量和类属性注解。默认模式下，字面量和简单构造调用产生的变量若从不重新赋值可省略注解，另提供严格模式要求每次赋值都显式注解。工具可通过 pip 安装并集成到 pre\-commit 流程，支持错误抑制语法，退出码为 0 表示无错误、1 表示有错误、2 表示用法错误。

**评论要点**:

有人认为Python中8080和'8080'的类型区分本就不含糊，强制到处写类型提示是对类型检查器的倒退，只在无法推断处要求提示才合理。另有人分享实践：仅对参数和返回值加类型检查，虽未直接发现bug，却暴露出返回类型不一致等意外问题，需额外研究才能确定正确类型。
